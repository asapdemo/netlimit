# NetLimit — Посібник користувача (українською)

NetLimit — інтерактивна термінальна програма (TUI) для **Linux**, яка дозволяє **симулювати погану або мобільну мережу** і **вимірювати** результат.

Можна обмежувати швидкість, додавати втрату пакетів, затримку та джитер, стежити за якістю шляху та запускати тест швидкості через Cloudflare — усе в одному темному інтерфейсі в стилі btop.

## 1. Що робить NetLimit

| Можливість | Опис |
|------------|------|
| **Обмеження завантаження** | Максимальна швидкість download (Мбіт/с) через IFB + HTB |
| **Обмеження відвантаження** | Максимальна швидкість upload (Мбіт/с) через HTB |
| **Втрата пакетів** | Відсоток випадкових втрат (`netem loss`) |
| **Затримка (delay)** | Базова латентність у мілісекундах |
| **Джитер (jitter)** | Варіація затримки в мілісекундах |
| **Якість шляху** | Живі графіки ICMP-втрат і RTT до `1.1.1.1` |
| **Тест швидкості** | HTTP throughput + latency через Cloudflare |
| **Історія** | Збережені результати тестів на диску |

Типові сценарії: тестування додатків у поганій мережі, демо, перевірка ISP під штучними обмеженнями, вивчення Linux traffic control.

## 2. Встановлення

### Залежності

```bash
# Debian / Ubuntu / Raspberry Pi OS
sudo apt update && sudo apt install -y iproute2

# Arch Linux
sudo pacman -S --needed iproute2

# Fedora
sudo dnf install iproute-tc
```

Також потрібен `ping` (зазвичай уже встановлений).

### Збірка з вихідного коду

```bash
git clone https://github.com/virtuoz-afk/netlimit.git
cd netlimit
cargo build --release
```

Шлях до бінарника:

```text
./target/release/netlimit
```

### Системне встановлення

```bash
sudo install -m 755 target/release/netlimit /usr/local/bin/netlimit
```

### Запуск

```bash
sudo netlimit
# або без встановлення:
sudo ./target/release/netlimit
```

### Корисні прапорці

```bash
netlimit --version
sudo netlimit -i wlan0          # обрати інтерфейс
sudo netlimit --no-sudo         # без повторного sudo (Apply все одно потребує root)
```

### Sudo і PATH

`sudo` часто **не бачить** `./target/release` або `~/.cargo/bin`. Краще:

```bash
sudo /повний/шлях/до/netlimit
# або встановити в /usr/local/bin
```

## 3. Перший запуск

1. Запустіть `sudo netlimit`.
2. Оберіть **мережевий інтерфейс** (лівий список; маршрут за замовчуванням позначено ★).
3. Налаштуйте метрики або оберіть **пресет**.
4. Натисніть **Apply** (`a`), щоб застосувати обмеження.
5. За бажанням відкрийте **Speed Test** (`t`).
6. Після тестів натисніть **Reset** (`r`).

## 4. Головний екран

Розкладка (зверху вниз):

| Блок | Вміст |
|------|--------|
| **Вгорі ліворуч** | Список інтерфейсів |
| **Вгорі праворуч** | **Поточні застосовані ліміти** |
| **Presets** | Швидкі профілі |
| **Метрики** | Download, Upload, Loss, Delay, Jitter |
| **Path quality** | Графіки втрат і затримки |
| **Дії** | Apply, Reset, History, Quit |
| **Банер** | Повідомлення статусу |
| **Підвал** | Підказки клавіш |

### Метрики

| Елемент | Одиниця | Значення |
|---------|---------|----------|
| **↓ Download** | Мбіт/с | Максимум завантаження (0 = без обмеження) |
| **↑ Upload** | Мбіт/с | Максимум відвантаження (0 = без обмеження) |
| **⚠ Loss** | % | Втрата пакетів |
| **⏱ Delay** | мс | Базова затримка |
| **∿ Jitter** | мс | Розкид затримки |

Значення в UI — це **чернетка**, поки ви не натиснете **Apply**.  
Панель **Current applied limits** показує те, що реально діє в системі.

## 5. Пресети

Вбудовані профілі за замовчуванням:

| Пресет | Призначення |
|--------|-------------|
| **No limits** | Без шейпінгу |
| **4G** | Мобільний LTE-подібний профіль |
| **3G** | Повільніший мобільний + більша затримка/втрати |
| **Starlink** | Висока швидкість, супутникова RTT/джитер |

| Дія | Як |
|-----|-----|
| Завантажити | Клік по чіпу або клавіші `1`–`9` |
| Зберегти поточні як свої | `s` або **+ Save** |
| Видалити свій | **×** на чіпі або вибір + `x` / `Del` |

Користувацькі пресети: `~/.config/netlimit/presets.json`.

## 6. Якість шляху (Path quality)

Використовує системний **`ping`** до **1.1.1.1** (DNS Cloudflare).

| Графік | Що показує |
|--------|------------|
| **Packet loss** | % невдалих ping у вікні; мітка якості (Excellent → Bad) |
| **Latency (RTT)** | Час туди-назад у мс; мітка якості |

Також видно живий трафік інтерфейсу (↓/↑ Мбіт/с з `/proc/net/dev`).

## 7. Тест швидкості Cloudflare

Відкривається клавішею **`t`** або кнопкою **Cloudflare Speed Test**.

### Тривалість

- **Sec/phase** (за замовчуванням **5**): кожна фаза (latency, download, upload) триває стільки секунд.
- Повний тест ≈ **3 × sec/phase** (наприклад 5 с → ~15 с).
- Крок зміни: `−` / `+` або `←` / `→` (Shift = ±5).

### Керування

| Елемент | Дія |
|---------|-----|
| **Run all** | Усі три фази |
| **↺ ↓ / ↑ / lat** | Повторити лише цю фазу |
| **Back** / `Esc` | На головний екран |

Графіки оновлюються під час прогонів. Активні ліміти NetLimit **впливають** на результат (це очікувано).

---

## 8. Історія

Клавіша **`h`** або кнопка **Hist**.

- Список нещодавніх тестів Cloudflare (час, Мбіт/с, latency, інтерфейс, знімок лімітів).
- Файл: `~/.config/netlimit/speedtest_history.json`.
- `Esc` / клік — назад на головний екран.

## 9. Клавіатура та миша

### Головний екран

| Клавіша | Дія |
|---------|-----|
| `↑` `↓` `Tab` | Обрати метрику |
| `←` `→` `+` `−` | Змінити значення |
| `Shift` + зміна | Більший крок |
| `d` `u` `l` `y` `j` | Фокус Download / Upload / Loss / Delay / Jitter |
| `1`–`9` | Завантажити пресет |
| `s` | Зберегти пресет |
| `x` / `Del` | Видалити свій пресет |
| `a` | Застосувати (Apply) |
| `r` | Скинути всі ліміти (Reset) |
| `t` | Тест швидкості |
| `h` | Історія |
| `i` `[` `]` | Цикл інтерфейсів |
| `q` / `Esc` | Вихід |

### Миша

- Клік по інтерфейсах, пресетах, ±, слайдерах, кнопках.
- Коліщатко над карткою метрики — крок значення.

## 10. Як працює traffic control

| Напрямок | Механізм |
|----------|----------|
| Upload | HTB + netem на **egress** інтерфейсу |
| Download | Ingress перенаправляється на **ifb0**, далі HTB + netem |
| Loss / delay / jitter | Параметри `netem` |
| Reset | Видалення qdisc; `ifb0` down |

Це обмеження **на весь інтерфейс** (не на окрему вкладку браузера).

## 11. Усунення несправностей

| Проблема | Що спробувати |
|----------|----------------|
| `sudo: netlimit: command not found` | Повний шлях або встановлення в `/usr/local/bin` |
| Apply не працює | Запуск від root; перевірити `tc` / `ip` |
| Download-ліміт не діє | `sudo modprobe ifb`; правильний інтерфейс |
| Тест швидкості падає | Мережа/DNS/фаєрвол; збільшити тривалість |
| Path quality «завмер» | Перевірити `ping -c 1 1.1.1.1` |
| Правила лишилися після збою | `sudo netlimit` → **Reset**, або вручну `tc qdisc` |

Перевірка стану ядра:

```bash
tc qdisc show
tc qdisc show dev ifb0
tc class show dev eth0
```

---

## 12. Безпека

- Ліміти стосуються **усього** трафіку на обраному інтерфейсі.
- Після тестів завжди робіть **Reset**.
- Не залишайте сильні loss/delay на робочих машинах без потреби.
